# Передача текущей калибровки оператору и разработчику

Дата: 2026-09-28. В обоих репозиториях ветка `codex/operator-calibration-handoff`.
Main не изменяется; слияние выполняет Алексей после проверки.

- Runtime: https://github.com/aleksey-yagubov/roki-ng/tree/codex/operator-calibration-handoff
- GUI: https://github.com/aleksey-yagubov/roki-ng-operator-gui/tree/codex/operator-calibration-handoff

## Что передано

В существующем GUI добавлены панели поля/ворот и цветов/камеры: LAB-пороги,
пипетка с автоподбором, локальные черновики и маска, управление камерой,
выбор своих ворот, геометрия поля и дополнительные метки. Параметры и defaults
читаются из runtime. Отдельного приложения редактора нет.

Runtime содержит пакетные форматы существующих params.set/params.get,
конфликт-контроль записи, управление камерой на следующих запросах,
фиксацию AE/AWB по свежим метаданным и схемы параметров поля.
В ветке сохранены также накопленные инструменты и диагностический worker
локализации, проекция на землю и цветовые наблюдения ворот. Это не завершённая
игровая локализация: диагностические результаты не означают достоверную позу.
См. LOCALISATION_RUNTIME_STATUS.md и отчёты экспериментов в runtime.

## Фактический путь изображения

runtime camera worker -> исходный BGR -> stream worker -> H.264/JPEG RTP ->
GStreamer GUI -> QImage -> зафиксированный уменьшенный снимок -> NumPy LAB-маска.
OpenCV оператору не требуется. Ползунки и пипетка работают локально без RTT.
Маска справа не поступает с робота и пока не обновляется как live-поток.
Detection worker на роботе отдельно читает исходный BGR и возвращает области
через detection.status; локальная маска не включает его отсев по площади.
Direct-gst не снабжает runtime detector кадрами; совместная проверка требует
runtime-камеры, control lease и MANUAL.

## Совместимость и установленный робот

GUI сохраняет набор через params.set {values, expected_values}; читает через
params.get {keys}. Прежние одиночные key/value форматы сохранены.
Отдельной wire-команды params.set_many нет; внутренний метод Parameters.set_many
остаётся. Число ключей 1..16, UDP не более 1200 байт; GUI читает по 8 значений.

На 192.168.0.120 применён только точечный патч пакетных параметров к ранее
установленному supervisor, сервис roki-head перезапущен. Проверены реальные UDP
чтение/запись с Mac и одиночное чтение; записаны прежние пороги без изменения
значений. Резервная копия не создавалась по просьбе разработчика.
Это НЕ развёртывание всей данной ветки: field/localisation/freeze и прочие
новые возможности требуют соответствующего обновления runtime.
Патч: runtime docs/patches/params-batch-installed-service.patch; повторно к уже
исправленному роботу не применять. Он привязан к прежней версии supervisor.

## Проверки

- Runtime: 77 целевых тестов параметров, камеры, геометрии и локализации прошли.
- GUI: все 36 unittest прошли на macOS с Qt/PySide6 6.7.3.
- GUI -> MessagePack -> настоящий dispatcher с mock workers: 118 запросов,
  максимальный пакет 587/1200 байт. Это не аппаратный end-to-end тест.
- GStreamer 1.28.7 + PyGObject 3.58.0: реальные локальные RTP H.264 и JPEG
  приняты MediaWorker до QImage 320x240.
- Основное окно GUI открыто на Mac; светлая палитра устраняет конфликт с тёмной
  темой ОС. См. GUI docs/MACOS.md, scripts/build_macos.sh, run_macos.sh,
  install_gstreamer_macos.sh и check_gstreamer.py.
- Полный runtime suite на macOS ранее имел 6 платформенных ошибок Unix
  seqpacket/worker-тестов; текущий прогон целевой, не подтверждает весь suite
  на Linux/Buildroot. GPU qml6glsink и физическая камера в локальном RTP-тесте
  не проверялись.

## Следующие шаги

1. Измерить влияние H.264: взять один и тот же исходный кадр и декодированный
   кадр, сопоставить размер/область и измерить различия LAB, масок (IoU,
   ложные/пропущенные пиксели) и областей на нескольких сценах/битрейтах.
   Не сравнивать случайные соседние кадры. Отдельно измерить влияние уменьшения
   снимка и различий NumPy/OpenCV LAB. Количественной оценки пока нет.
2. По результатам решить, сохранять ли быстрый локальный preview или добавлять
   diagnostic stream 1600x650 (исходник + серверная маска/рамки). Последний пока
   только обсуждён, не реализован.
3. Увеличить просмотр и добавить live-обновление; сейчас snapshot.
4. Довести UX запуска детектора: кнопка доступна по lease, но команда требует
   MANUAL; локальный отказ Control не всегда отражается в notice панели.
   Проверить запуск, профиль, свежесть результатов на реальном роботе.
5. Полная проверка field/freeze/localisation после согласованного обновления
   runtime; калибровочный мастер объектива и импорт npy ещё не реализованы.

Не выдавать локальный image_serial за UnicamSequence: точная связь RTP-кадра
и серверных детекций пока не реализована. Не объявлять готовой локализацию
только по визуально удачному bird-view.
