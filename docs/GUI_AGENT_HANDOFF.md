# Агенту программы оператора

Исходники головы: [aleksey-yagubov/roki-ng](https://github.com/aleksey-yagubov/roki-ng).
Это новый runtime, не старый manual_msgpack_server. Файл
[OPERATOR_PROTOCOL_V1.md](OPERATOR_PROTOCOL_V1.md) описывает реализованные
операции. [PROTOCOL_AND_MEDIA.md](PROTOCOL_AND_MEDIA.md) описывает целевую
архитектуру; не считать все перечисленные там операции работающими.

## Что подключать сейчас

- Настройки траектории теперь в `walk.*`: max_step_mm, max_side_mm,
  max_yaw_rad, step_height_mm, servo_frames_per_pose, body_tilt_forward,
  body_tilt_backward, sole_skew, gait_height_mm, sway_amplitude_mm,
  heading_kp, heading_max_correction_rad, crouch_transition_frames. Описания/единицы/диапазоны брать
  из params.describe. Старые имена не поддерживаются и не мигрируются.
  Измеренные калибровки остаются в motion.*; наклон удара и стопы удара —
  kick.body_tilt и kick.sole_skew. Дефолты существующих настроек не изменены.
  Ручной `heading_hold` реализован: bool в каждом motion.drive, default false.
  Отдельная галочка «Удерживать курс по IMU тела». Не относится к IMU головы,
  видео и стабилизации равновесия; heading_* общие с шаговыми тестами.

- UDP MessagePack на фиксированный адрес и порт 8093, без discovery.
  Один control socket для requests, responses, событий, данных и логов.
- Использовать capabilities/каталоги tests/slots/params; список слотов
  запрашивается явно, не присылается автоматически при hello.
- Поддержать control lease/takeover, heartbeat, дедупликацию запросов,
  motion stop и disconnect. Проверить uint64 ID в Python, не округлять их QML Number.
- Видео запрашивается отдельно. Direct-gst и runtime camera являются разными
  путями; runtime video не должен повторно открывать занятую camera-worker камеру.
- Логи через log.subscribe/log.sample, данные через data.*. У текущих базовых
  state-topics источник heartbeat, это не высокочастотная телеметрия датчиков.
- Для интеграционных проверок использовать roki_ng/client.py и supervisor
  --simulate на localhost. --test-video включает реальное тестовое RTP-видео
  без камеры. Не требуется подключать тело для проверки GUI/протокола.

## Ручные движения: реализовано 2026-09-29

- Удалить галочку автоподготовки и поле `auto_prepare` из motion.drive.
  Робот сам выполняет необходимый переход в crouch по новой команде ходьбы.
  Из сохранённого crouch повторной подготовки нет.
- `hold_crouch` удалён. Вместо него `crouch: "off" | "on" | "centered"`,
  отсутствует = off. Две галочки: «Оставаться в приседе» и зависимая от неё
  «Центрированный присед». Первая снята: off; первая включена: on/centered.
  Передавать режим с drive (включая нулевые samples), jump, get_up и splits.
  Явная кнопка Crouch отправляет motion.pose с name=crouch и crouch=on/centered
  независимо от галочки «Оставаться»: эта кнопка всегда означает присесть.
- `motion.jump` с on/centered готовит выбранный присед, если нужен, затем
  выполняет прыжок без вставания. Если поза уже совпадает, подготовки нет.
  Из base_stand присед не выполняется даже при on/centered: прыжок сохраняет
  базовую стойку. GUI не должен добавлять предварительную команду Crouch.
  Прыжковые повороты и перемещения
  посылают команды только участвующим суставам, не обнуляя остальные и не
  вызывая вставание. Задействованные суставы возвращаются к исходным целевым
  положениям. После завершения сохраняются crouch и состояние походки.
  При off или отсутствии поля действует прежний абсолютный слот. Проверено
  программными тестами, физическая устойчивость пока не проверялась.
- Добавить кнопку «Встать после падения»: motion.get_up с crouch. Положение
  определяет IMU тела. Нет ручного ожидания 0,5 с. Ошибка проверки после
  вставания выдаётся как failed, повтор автоматически не выполняется.
- Добавить кнопки «Splits» и «Шпагат»: motion.splits с kind=small/big и crouch.
  Вход включает подготовку. Возврата нет: оператор жмёт Crouch/Stand/Base stand.
  Состояния позы дополнены crouch_centered, splits_small, splits_big;
  не считать их ошибкой или неизвестной позой. Новые движения требуют
  физической проверки на стойке, особенно боковой get_up и выход из шпагата.
- walk.crouch_transition_frames задаёт интерполяцию центрирования, переноса
  веса перед ходьбой и выхода из splits; default 20 кадров (400 мс при 20 мс/кадр).
  Hard stop по-прежнему сбрасывает очередь головы, не обесточивает сервы
  и не отменяет уже принятую интерполяцию. Busy-команды не накапливать в GUI.
- Бэкэнд Kondo фиксирован в реализации, настройки выбора транспорта нет.
  units в файлах слотов описывает только значения, не способ связи с телом.
- Автономную игру этим изменением не затрагивать: ей необходимо согласование
  опорной позы и высоты камеры с локализацией. Ручной приём не считать
  автоматически пригодным для автономного восстановления равновесия.
- По опыту оператора на «Ходоке», повторные прыжковые повороты помогали
  стабилизировать робота при заваливании. На ROKI2 это требует проверки;
  не добавлять накопление команд или автоматическое спасение прыжками.
- Код движений «Ходока» исходно сторонний. Изменения оператора: сокращение
  ожиданий стабилизации, ускорение движений (особенно splits, использовавшегося
  как удар) и перенос переходов присед/вставание на кнопки пульта.

### Другие расширения

- [DISPLAY_PROTOCOL.md](DISPLAY_PROTOCOL.md): OSD через MessagePack; в RTP только
  UnicamSequence. Ни точная extension, ни OSD sample пока не реализованы.
  Рисование Qt6 без OpenCV; поздний OSD не замедляет live-видео, отсутствие
  соответствующего кадра явно показывается в диагностическом окне.
- [COLLABORATION_HANDOFF.md](COLLABORATION_HANDOFF.md): схемы детекторов,
  локализации и стратегии должны быть согласованы вместе с их разработчиком.
  Поле/робот/мяч/цель, IMU и сервостатусы являются datastream, не video OSD.
- [CALIBRATION_AND_RECOVERY.md](CALIBRATION_AND_RECOVERY.md): калибровка fisheye
  по мишени, редактор профилей конкретного поля. Отдельно черновик, сохранение
  и применение; не менять геометрию работающей локализации по одному полю.
- Калибровочные таблицы уже используются старым кодом в .npy. В новой системе
  они остаются предрассчитанными файлами на роботе; GUI получает метаданные,
  качество и preview, а не огромные массивы через обычный UDP sample.
- Универсальные defaults поставляются с программой. Индивидуальные параметры,
  .npy и профили поля сохраняются в /var/lib/roki-ng, не в Git и не в общей сборке.

Не создавать параллельный wire-протокол: новые схемы и примеры сначала
фиксируем в roki-ng, затем совместно реализуем клиент и сервер. Старые команды
не переименовывать без версии/capability. Полный автономный футбол, localization,
neural worker и редактор серв пока не реализованы; GUI не должен заявлять обратное.

GUI не общается с Roki.so/ACM напрямую и не нуждается в их сборке на ноутбуке.
Обновление native Roki и motherboard firmware относится к образу робота.

## Эксперимент удержания приседа, 2026-09-30

Добавлены запрашиваемые `body.imu` и `body.stabilization` (до 10 Гц оператору).
Подписка включает только чтение, не движение и не владение роботом. IMU тела
отдельна от синхронной IMU головы; timestamp = получение ответа на голове.
GUI должен проверять valid/age_ms и не рисовать старый горизонт как актуальный.

Для эксперимента: обычный редактор `stabilization.*` с описаниями params.describe,
отдельное включение stabilization.enabled (default false), графики pitch,
offset_deg и reason/saturated. По умолчанию не включать при подключении!
Менять параметры между задачами. base_stand пока не регулируется.
Выключение удержания сохраняет текущую поправку; без отдельной команды возврата.
Подробности: [CROUCH_STABILIZATION.md](CROUCH_STABILIZATION.md) и раздел
IMU тела в [OPERATOR_PROTOCOL_V1.md](OPERATOR_PROTOCOL_V1.md).
Новые команды GUI не обязательны: используются существующие params/data.

## Чтение позиций серв

Добавлены `motion.joints` (постраничный каталог) и datastream `body.servos`,
до 5 Гц. Массивы measured/nominal/sent по unit0..29 в единицах Зубра,
градусы = значение*360/16384. Sent включает поправку стабилизации. Неизвестные
цели null. Для графиков: измеренное, заданное и разность; рядом IMU тела.
Это чтение RAM, не статус связи каждой сервы. В UI обязательно показать
ограничение свежести и не объявлять неисправность по одному расхождению.
Полная схема и оговорки: OPERATOR_PROTOCOL_V1.md, раздел body.servos.

Пользователь наблюдает данные через подписки в GUI, без отдельных консольных
наблюдателей. Диагностику реализуем внутри runtime с выводом через обычные
datastream и log.subscribe. Отдельный CLI для оператора не нужен.

Тестовая диагностика включается `stabilization.diagnostics_enabled=true`
через params.set между задачами (default false). Сама включает опрос позиций
5 Гц и IMU, но не стабилизатор. В обычном логе до трёх строк в секунду:
pitch/поправка/причина, затем nominal/sent/measured для ID7 справа и слева.
В body.stabilization добавлен diagnostics: enabled, status, servo_sequence,
source_mono_ns, hip_error_deg=[R,L], consecutive=[R,L]. Это наблюдение,
не новый контур управления. WARNING означает устойчивое расхождение, не
доказанный отказ мотора; свежесть каждой сервы всё ещё неизвестна.

## Напряжение аккумулятора: body.power

Добавлен источник `body.power` в `data.list`, стандартные `data.snapshot`,
`data.subscribe/update/unsubscribe`; нового типа пакетов нет. Доступен наблюдателю
без управления, камеры и движений. Подписка:
`data.subscribe {"topic":"body.power","rate_hz":1}` (максимум и default 1 Гц).

В `data.sample.body.data`: `voltage_v` (готовые вольты), `adc_raw` (диагностика),
`valid`, `source_mono_ns`, `timestamp_kind`, `sequence`, `simulated`,
`busy_reads`, `invalid_reads`, `error`. Проверять `body.valid` и `body.age_ms`:
после 3 с данные устарели. Не показывать null/ошибку как 0 В, не выдавать
напряжение за процент заряда. При `simulated=true` обозначать симуляцию.
Пересчёт ADC уже выполняет робот; GUI показывает, например, `12.04 В`.

Полное описание: раздел «Напряжение аккумулятора» в `OPERATOR_PROTOCOL_V1.md`.
