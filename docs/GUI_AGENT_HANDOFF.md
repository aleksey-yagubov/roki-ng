# Агенту программы оператора

Исходники головы: [aleksey-yagubov/roki-ng](https://github.com/aleksey-yagubov/roki-ng).
Это новый runtime, не старый manual_msgpack_server. Файл
[OPERATOR_PROTOCOL_V1.md](OPERATOR_PROTOCOL_V1.md) описывает реализованные
операции. [PROTOCOL_AND_MEDIA.md](PROTOCOL_AND_MEDIA.md) описывает целевую
архитектуру; не считать все перечисленные там операции работающими.

## Что подключать сейчас

- Настройки траектории теперь в `walk.*`: max_step_mm, max_side_mm,
  max_yaw_rad, step_height_mm, servo_frames_per_pose, body_tilt_forward,
  body_tilt_backward, sole_skew, gait_height_mm, sway_amplitude_mm,
  heading_kp, heading_max_correction_rad. Описания/единицы/диапазоны брать
  из params.describe. Старые имена не поддерживаются и не мигрируются.
  Измеренные калибровки остаются в motion.*; наклон удара и стопы удара —
  kick.body_tilt и kick.sole_skew. Дефолты существующих настроек не изменены.
  Ручной heading_hold пока согласован, но ещё не реализован; коэффициенты
  heading_* сейчас используются в удержании курса шаговых тестов.
  Не считать наличие параметров наличием нового флага команды.

- UDP MessagePack на фиксированный адрес и порт 8093, без discovery.
  Один control socket для requests, responses, событий, данных и логов.
- Использовать capabilities/каталоги tests/slots/params; список слотов
  запрашивается явно, не присылается автоматически при hello.
- Поддержать control lease/takeover, heartbeat, дедупликацию запросов,
  motion stop и disconnect. Проверить uint64 ID в Python, не округлять их QML Number.
- Видео запрашивается отдельно. Direct-gst и runtime camera являются разными
  путями; runtime video не должен повторно открывать занятую camera-worker камеру.
- Логи через log.subscribe/log.sample, данные через data.*. У текущих базовых
  state-topics источник heartbeat, это не высокочастотная телеметрия датчиков.
- Для интеграционных проверок использовать roki_ng/client.py и supervisor
  --simulate на localhost. --test-video включает реальное тестовое RTP-видео
  без камеры. Не требуется подключать тело для проверки GUI/протокола.

## Ближайшие расширения: сначала согласовать

### Ручные движения: уточнение 2026-09-28

- Удалить галочку автоподготовки и поле `auto_prepare` из motion.drive.
  Робот сам выполняет необходимый переход в crouch по новой команде ходьбы.
  Из сохранённого crouch повторной подготовки нет. `hold_crouch` остаётся.
- Реализовано для ручного режима: `motion.jump` с `hold_crouch=true`.
  Передавать значение галочки также с поворотами и прыжковыми перемещениями.
  Требуется уже принятый crouch; флаг не вызывает автоматический присед.
  Прыжковые повороты и перемещения
  посылают команды только участвующим суставам, не обнуляя остальные и не
  вызывая вставание. Задействованные суставы возвращаются к исходным целевым
  положениям. После завершения сохраняются crouch и состояние походки.
  При false или отсутствии поля действует прежнее поведение. Проверено
  программными тестами, физическая устойчивость пока не проверялась.
- Автономную игру этим изменением не затрагивать: ей необходимо согласование
  опорной позы и высоты камеры с локализацией. Ручной приём не считать
  автоматически пригодным для автономного восстановления равновесия.
- По опыту оператора на «Ходоке», повторные прыжковые повороты помогали
  стабилизировать робота при заваливании. На ROKI2 это требует проверки;
  не добавлять накопление команд или автоматическое спасение прыжками.
- Код движений «Ходока» исходно сторонний. Изменения оператора: сокращение
  ожиданий стабилизации, ускорение движений (особенно splits, использовавшегося
  как удар) и перенос переходов присед/вставание на кнопки пульта.

### Другие расширения

- [DISPLAY_PROTOCOL.md](DISPLAY_PROTOCOL.md): OSD через MessagePack; в RTP только
  UnicamSequence. Ни точная extension, ни OSD sample пока не реализованы.
  Рисование Qt6 без OpenCV; поздний OSD не замедляет live-видео, отсутствие
  соответствующего кадра явно показывается в диагностическом окне.
- [COLLABORATION_HANDOFF.md](COLLABORATION_HANDOFF.md): схемы детекторов,
  локализации и стратегии должны быть согласованы вместе с их разработчиком.
  Поле/робот/мяч/цель, IMU и сервостатусы являются datastream, не video OSD.
- [CALIBRATION_AND_RECOVERY.md](CALIBRATION_AND_RECOVERY.md): калибровка fisheye
  по мишени, редактор профилей конкретного поля. Отдельно черновик, сохранение
  и применение; не менять геометрию работающей локализации по одному полю.
- Калибровочные таблицы уже используются старым кодом в .npy. В новой системе
  они остаются предрассчитанными файлами на роботе; GUI получает метаданные,
  качество и preview, а не огромные массивы через обычный UDP sample.
- Универсальные defaults поставляются с программой. Индивидуальные параметры,
  .npy и профили поля сохраняются в /var/lib/roki-ng, не в Git и не в общей сборке.

Не создавать параллельный wire-протокол: новые схемы и примеры сначала
фиксируем в roki-ng, затем совместно реализуем клиент и сервер. Старые команды
не переименовывать без версии/capability. Полный автономный футбол, localization,
neural worker и редактор серв пока не реализованы; GUI не должен заявлять обратное.

GUI не общается с Roki.so/ACM напрямую и не нуждается в их сборке на ноутбуке.
Обновление native Roki и motherboard firmware относится к образу робота.
