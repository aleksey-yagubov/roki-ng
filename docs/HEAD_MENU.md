# Меню кнопок головы

Голосовое меню реализовано в supervisor, без вывода на экран. Озвучка на
английском через espeak. Работают навигация и запуск существующих тестов.
Игровые стратегии ещё не перенесены: окончательное подтверждение в ветке
Football произносит `Football not available yet`, не запускает движение,
камеру или фиктивную игру. Описанная ниже игровая пауза будет подключена вместе
с игровым воркером.

## Включение и зависимости

На голове меню включено по умолчанию после запуска воркеров. Для диагностических
запусков без кнопок и озвучки есть `--no-head-menu`; при `--simulate` меню
автоматически не подключается. Нужны Python evdev и исполняемый файл `espeak`,
доступ к input-устройству `roki-head-buttons` и ALSA.

Устройство открывается по имени, а не по меняющемуся номеру eventN. Меню не
делает exclusive grab: отдельная служба кнопки питания продолжает получать
KEY_POWER. Она не изменена. Старый main.py с обработкой Process reload нельзя
запускать одновременно с roki-ng.

## Запуск

После запуска и подтверждения готовности всех обязательных воркеров supervisor
однократно произносит `Ready`. Затем становится доступно меню кнопок.
Недостаточно просто создать процессы: их инициализация должна завершиться.
При ошибке запуска сообщение `Ready` не произносится.

Готовность означает готовность runtime принимать команды, а не запуск игры,
камеры или движения. Отсутствующее тело, обработанное motherboard-worker как
degraded, не блокирует меню; команды движения по-прежнему отклоняются до
восстановления связи.

## Кнопки

- Верхняя левая: назад / отменить.
- Верхняя правая: подтвердить.
- Нижние: предыдущий / следующий пункт.
- Одно нажатие выполняет одно действие; удержание и автоповтор не меняют выбор.

По текущему device tree: F14/BTN2 = назад, F15/BTN3 = OK,
F13/BTN1 = влево, F16/BTN4 = вправо. Обрабатывается только нажатие EV_KEY=1;
до отпускания повторные события той же кнопки игнорируются. При потере событий
evdev состояние удерживаемых кнопок перечитывается без выполнения действий.
Голосовые сообщения не накапливаются: новое прерывает предыдущее.

## Структура

```text
Game
  Football
    Goalkeeper
    Forward
      Left
      Center
        Start
        Start later
      Right
Tests
  Rotation right
  Short run
  Long run
  Spot run
  Kick test
  Side step left
  Side step right
  Get up test
  Other tests
```

`Start later` означает задержку 10 секунд и доступен только для Forward Center.
Разделы Body, Operator и Status не нужны. Расслабление тела и возвращение
в ровную стойку выполняются выделенными кнопками контроллера тела.

## Выполнение тестов

OK на выбранном тесте запускает существующий test.start. Название Rotation right
сохранено для привычного меню; оно вызывает общую старую процедуру rotation_test,
которая калибрует оба направления, а не только одиночный поворот вправо.
Short/Long/Spot run передают соответствующий mode в run_test, Kick test вызывает
regular. Боковые шаги доступны в основном списке. В Other tests вынесены ходьба
назад и пять направлений
прыжков. После завершения выбранный пункт остаётся на месте для повторного пуска.

Get up test определяет положение по IMU тела и при необходимости выполняет
один подходящий слот подъёма, затем проверяет вертикальное положение. Если
робот уже стоит, команды сервам не отправляются. Такая же проверка и подъём
выполняются перед остальными тестами, включая удар. Ошибка IMU, неоднозначное
положение или неудачный подъём завершают тест, а не запускают ходьбу/удар.
Это не фоновое автоматическое вставание во время любых движений.

Назад во время теста запрашивает job.cancel. Звучит `Stopping`, а `Stopped` —
после подтверждённого окончания. Новые пуски до окончания не накапливаются.
Во время самого подъёма Назад сбрасывает очередь, а не доигрывает весь слот;
это может оставить робота в промежуточной позе, поэтому при проверках его
нужно страховать. Reset не останавливает уже выполняемую интерполяцию серв.
При успешном завершении звучит `Test completed`, при ошибке — `Test failed`.
Сохранение калибровок выполняется существующим supervisor, не самим меню.

Меню получает локальное владение управлением только на время теста, через те же
проверки, что UDP-клиент. Пока GUI владеет управлением, звучит `Control busy`;
для проверки тестов кнопками нужно освободить управление в GUI или отключиться.
Меню не отбирает lease у оператора. Обратное разрешено: оператор может в любой
момент вызвать `control.acquire {"force":true}`. Меню произносит `Operator control`,
отменяет свой ожидающий запуск; текущий тест прерывается сбросом очереди.
Подробности неподтверждённой остановки описаны в OPERATOR_PROTOCOL.md.
Без тела звучит `Body unavailable`.
После восстановления связи старые движения не возобновляются. Явно запущенный
тест выполняет собственную проверку IMU/подъём. Ручные команды доступны без
обязательной recovery-позы; старые команды автоматически не повторяются.

Навигация не запускает камеру, не запрашивает нейроускоритель и не перезапускает
процессы. Меню слушает evdev асинхронно, завершение тестов — через worker events;
ожидание озвучки не блокирует heartbeat и канал управления.

## Стратегия вратаря

Пункт `Game -> Football -> Goalkeeper` должен запускать логику старой стратегии
`FIRA_penalty_Goalkeeper`: по проверке пользователя нормально работала именно
она. Не подменять её `goalkeeper` или `penalty_Goalkeeper`. Название пункта
и озвучка остаются `Goalkeeper`; слово FIRA не требуется в меню.

## Пауза игры

Первое нажатие назад останавливает игру с завершением текущего шага; после
остановки звучит `Paused`. В паузе нижние кнопки выбирают позицию ввода
нападающего Left / Center / Right. OK продолжает игру с выбранной начальной
позицией локализации, а не перемещает робота туда. Вратарь продолжает без
выбора позиции ввода. Повторное нажатие назад в паузе завершает игру и
возвращает меню футбола. Пауза не перезапускает процессы и оборудование.
