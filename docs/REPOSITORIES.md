# Репозитории для совместной разработки

Состояние на 27.09.2026: motherboard firmware и interface опубликованы в своих
fork; roki-ng создан и опубликован. Дальнейшую работу над новым
протоколом разъёма головы контроллера будем вести отдельными ветками в firmware
и interface; эти ветки пока не создавались.

| Репозиторий | Предлагаемое действие |
| --- | --- |
| roki-ng | Создан aleksey-yagubov/roki-ng; runtime, контракты, defaults, тесты. Здесь основная совместная работа над алгоритмами |
| [roki-ng-operator-gui](https://github.com/aleksey-yagubov/roki-ng-operator-gui) | Уже существует: Qt/QML-клиент, редактор параметров, транспорт оператора. Расширять существующий GUI; протокол определяется в roki-ng, не копируется независимым документом |
| roki-buildroot | Уже есть origin aleksey-yagubov/roki-buildroot; использовать существующий |
| Roki_2_Soccer | Форк оригинального проекта babaev1 уже есть у пользователя; сохранить как источник старого кода |
| roki-mb-firmware | Форк tndrd/roki-mb-firmware; наши изменения опубликованы, бинарные артефакты находятся в GitHub Release |
| roki-mb-interface | Форк tndrd/roki-mb-interface; ACM v2 и исправления Roki опубликованы, собирается Buildroot под целевую платформу |

Upstream-адреса подтверждены локальными remote, .gitmodules и рецептом Buildroot.
Локальные firmware/interface теперь имеют origin на пользовательские fork.
История upstream сохранена; зависимости сверены с закреплёнными commits.

Отдельный fork rcb4-base-class пока не обязателен: локальная сборка использует
закреплённый upstream, а показанные исправления реализованы в RokiRcb4 поверх
него. Локальные файлы этих зависимостей совпали с закреплёнными commits.
Аналогично roki-mb-service сейчас нужен как зависимость заголовков;
не создавать лишние forks без фактических изменений.

Форк roki_next_generation не требуется для запуска roki-ng. При переносе
алгоритмов сохранять авторство, ссылку на исходный commit и условия лицензии.
Код и контракты новых алгоритмов интегрировать в roki-ng, не публиковать всю
рабочую папку с образами, дампами и чужими проектами.

## Перед первым push

- Согласовать права и лицензию: корневых LICENSE в просмотренных roki-ng,
  Roki_2_Soccer и roki-mb-interface не найдено; это не разрешение автоматически
  лицензировать весь перенесённый код как MIT. Buildroot помечает Roki unknown.
- Проверить staged-файлы на пароли, ключи, реальные калибровки, firmware blobs
  с ограничениями распространения и журналы с персональными данными.
- Не включать `/var/lib/roki-ng`, rootfs, toolchains, build artifacts и записи
  кадров конкретного робота. Нужные бинарные релизы firmware публиковать отдельно
  с provenance, совместимостью и SHA256, если разрешено их распространение.
- Добавить воспроизводимую установку и host-тесты. Для новых контрактов нужны
  общие примеры сообщений и тесты совместимости GUI/runtime.
- Закрепить commit firmware + native Roki + runtime + Buildroot, проверенные
  вместе; не считать произвольные latest версии совместимыми.

Прошивочная утилита и motherboard firmware принадлежат firmware-репозиторию;
roki-ng документирует совместимость и сервисный порядок, но не прошивает STM
автоматически. Репозиторий операторского протокола отдельно пока не нужен:
схемы и примеры можно версионировать в roki-ng и использовать обеими сторонами.
