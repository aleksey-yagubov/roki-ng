# Исправление жёлтого изображения, 27.09.2026

Причина: runtime отключал AwbEnable, не задавая ColourGains. На голове это
давало коэффициенты R/B = 1/1 и выраженную желтизну. Полученные временным AWB
значения 1.1907840967178345 / 2.6072752475738525 исправили изображение и при
отключённой автоматике. Это измерение для текущего освещения, не универсальная
цветовая калибровка всех роботов.

## Реализовано

Два параметра существующего params API:

- `camera.white_balance.red_gain`;
- `camera.white_balance.blue_gain`.

Тип float, диапазон 0.01..32, apply=`next_request`. Подготовленная камера также
проверяет диапазон собственного ColourGains. Начальные значения 1/1 остаются
некалиброванными defaults. Индивидуальные значения хранятся в parameters.json
в каталоге состояния робота. В существующем GUI доступны через каталог параметров,
группу camera; отдельная панель и camera.controls.* пока не реализованы.

Camera.start передаёт ColourGains в libcamera вместе с ручными AE/AWB.
Во время захвата params.set отправляет обновлённую пару через следующий свободный
Request после reuse перед queue_request, без stop/start/configure. Изменение
одного коэффициента сохраняет второй. Подтверждение params.set означает принятие
и сохранение значения, не немедленное изменение уже находящихся в ISP кадров.
Параметры можно сохранять и при остановленной камере: они применятся при старте.
Direct-gst, предназначенный для ручного управления, этим изменением не затронут.

## Проверка на голове 192.168.0.119

Обновлены только camera.py, parameters.py и supervisor.py. Измеренные коэффициенты
записаны в /var/lib/roki-ng/parameters.json. Перед установкой сервис был свободен
(IDLE, без владельца и захвата); сохранена резервная копия в
`/var/lib/roki-ng/backups/wb-11329532208839`.

Непрерывный захват установленным Camera, без подмены start-контролов:

| Кадр | UnicamSequence | ColourGains из metadata | Результат |
| --- | --- | --- | --- |
| 120 | 123 | 1.1907841 / 2.6072752 | Желтизна устранена |
| 240 | 243 | 1 / 1 | Желтизна воспроизводится |
| 360 | 363 | 1.1907841 / 2.6072752 | Желтизна снова устранена |

360 кадров, bad_frames=0. AE/AWB выключены; выдержка 7989 мкс, analog gain=1.
Этот тест выполнялся без IMU. Затем через основной сервис проверен захват с IMU:
до/после params.set frames=122/244, sequence=125/247, bad_frames=0,
imu_sync=synced, Unicam-STM=5 до и после. После теста захват остановлен,
управление освобождено. Сервис roki-head снова запущен.

Снимки и метаданные на голове: /tmp/roki-wb-fixed/awb-off-{120,240,360}.{png,json}.
Они не включаются в Git, как и индивидуальные настройки.

## Автоматические проверки

34 теста WB/capture/detection прошли на Mac. Проверены стартовые controls,
обновление без перезапуска, неверные числа и диапазоны, сохранение и откат
worker-настроек при ошибке записи. Полный прогон до добавления двух последних
проверок: 121 passed, 2 skipped, 6 failed. Шесть интеграционных проверок не смогли
запустить worker-ы на macOS: `Startup failed: [Errno 43] Protocol not supported`.
Полный набор не объявляется прошедшим; работа реального Linux runtime проверена
отдельно на голове, как описано выше.

калибровки остаются следующим этапом по согласованной CAMERA_CONTROLS_PROPOSAL.md.
