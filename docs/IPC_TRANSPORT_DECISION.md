# Транспорт данных: iceoryx2

> Актуализация от 24 сентября 2026: интеграция iceoryx2 отложена. Пользователь
> допускает копирование кадров и просит подобрать более простой готовый транспорт.
> Ниже сохранено предыдущее решение, но это больше не окончательный выбор.
> Результаты сравнения: [IPC_ALTERNATIVES.md](IPC_ALTERNATIVES.md).

Решение от 24 сентября 2026: использовать iceoryx2 вместо собственного SPMC
ring и собственной обёртки libatomic. Сборку библиотеки можно добавить в образ.

Это решение заменяет прежний проект memfd/seqlock/eventfd rings из
INTERNAL_IPC.md и PROCESS_ARCHITECTURE.md. Там пока сохранено описание прежнего
варианта; оно не является заданием на реализацию собственных атомиков.

## Границы решения

- Кадры, IMU и результаты обработки передавать через shared-memory pub/sub.
- Команды supervisor, urgent stop и логи оставить на существующих Unix sockets.
- Операторский UDP/MessagePack не менять из-за выбора внутреннего транспорта.
- Имена каналов и граф потребителей задавать заранее; приложение не ищет сервисы.
  Внутренний учёт участников iceoryx2 остаётся частью библиотеки.
- Очереди ограничивать; для кадров разрешать вытеснение старых сообщений.
  Проверить лимиты удерживаемых samples и расход памяти при медленном читателе.
- Историю IMU для поиска по stm_sequence вести ограниченно у потребителей.
  Согласовать окончательный API истории при интеграции, не выдавать pub/sub за
  готовое индексируемое хранилище.

## Состояние реализации

Удалены черновые ring.py, ctypes/libatomic и привязанный к ним прототип
ImuProvider, а также передача их FD через SCM_RIGHTS. Рабочее разовое чтение
IMU тела в тестах движений сохранено. iceoryx2 ещё не интегрирован; runtime
camera-worker и постоянное чтение strobe IMU ещё не реализованы.

Следующий шаг: небольшой стенд iceoryx2 с кадрами 800x650 BGR при 60 кадрах/с,
несколькими читателями, задержками, SIGKILL и перезапуском процессов. Проверить
целостность кадров, пропуски, память и отсутствие блокировки producer.

## Проверки только с головой

Головы с CM4, камерой и motherboard достаточно для захвата, strobe IMU и
межпроцессного транспорта. Контроллер тела и сервоприводы не нужны.

Перед аппаратными проверками добавить отдельный режим без тела: не создавать
Rcb4, не выполнять checkAcknowledge, mixing и команды движений. Текущий
--skip-mixing пропускает только mixing, но не проверку контроллера тела, поэтому
его одного недостаточно. IMU тела и движения без тела проверить нельзя.

Снять reset только userspace-motherboard-reset и вывести STM из загрузчика;
userspace-bluecoin-reset оставить без изменений. Перед каждым новым runtime
capture выполнять согласованный reset strobe STM и полный start камеры.
