# Обработанное видео локализации

Во вкладке «Локализация» запустите камеру с IMU и локализацию, затем нажмите
«Видео с разметкой». Обычный поток runtime может работать одновременно:
штатный stream worker обслуживает два независимых pipeline. Обработанное видео
отображается в этой же вкладке. Остановка подписки не останавливает локализацию,
камеру или основной поток. Подписка создаётся только при явном запуске видео.

Без video.start локализатор не рисует и не публикует размеченный BGR.
Запросом служит подписка FrameReader стрим-воркера на LOCALISATION_TOPIC:
её наличие проверяется через dynamic_config iceoryx2 перед рисованием каждого
диагностического кадра. После закрытия подписки рисование прекращается;
повторный запуск видео возобновляет его на новых результатах без перезапуска
локализации. Создание описания video.create и подписка на localisation.state
рисование не включают. Канал publisher остаётся открытым до остановки локализации,
но без потребителя не берёт loans и не копирует пиксели. Уже начатое рисование
может завершиться после остановки видео; перед публикацией спрос проверяется снова.
Перевод OSD на MessagePack/Qt остаётся отдельной задачей: этот видеовыход
не является реализацией ранее обсуждавшегося display protocol.

Ошибка подготовки/публикации размеченного видео теперь отключает этот выход до
следующего localisation.start и пишет WARNING; результаты локализации продолжают
обновляться. Если RTP уже запущен, отсутствие новых кадров завершит его штатным
таймаутом. Фатальная ошибка самих вычислений отдельно сообщается в ERROR и
localisation.fault. Пустая область поля является пропущенным наблюдением, не
фатальной ошибкой.

Поток данных:
1. Камера публикует исходный BGR 800×650 с Unicam sequence и timestamp.
2. Локализатор сопоставляет его с IMU, находит разметку, считает позу.
3. Найденные отрезки и круг проецируются обратно в исходное изображение через
   ту же калибровку и quaternion. На кадре рисуются кандидаты стоек и оценка.
4. Кадр публикуется в `roki/localisation/frame/v1` в формате FRAME_HEADER + BGR,
   сохраняя sequence/timestamp исходного кадра.
5. Stream worker читает этот источник и кодирует обычный H.264/RTP.
6. Оператор декодирует видео в QImage. OpenCV на операторе для этого не нужен.

В существующем video.create добавлено значение backend="localisation".
Sensor не передаётся, максимальный выход 800×650. video.start требует работающих
runtime-камеры и локализатора. В общей панели выбирается runtime (по умолчанию) либо отдельный direct-gst.
Direct-gst требует эксклюзивного владения камерой и не используется параллельно
с runtime-захватом.
Панель локализации использует H.264, 2 Мбит/с, UDP 5006, nominal caps 30 FPS.
Фактическая частота равна частоте вычислений: каждый завершённый обработанный кадр
публикуется, накопления очереди нет, при перегрузке выбирается последний кадр.
Повторные кадры для искусственного повышения FPS не генерируются.

Обозначения:
- синие/жёлтые рамки: стойки, прошедшие геометрические проверки по matched-позе;
- фиолетовый: найденный круг;
- зелёный отрезок: остаток по выбранной гипотезе меньше 10 см;
- оранжевый: больший остаток; серый: нет гипотезы для сравнения.

Зелёные отрезки сами по себе не подтверждают позу: на симметричном поле возможно
несколько решений. Номер кадра, fit_state, число линий/пар ворот и reason нанесены
на сам кадр до кодирования. Русские пояснения текущей телеметрии под видео
сообщают о слабой геометрии, отсутствующем круге/паре стоек, неоднозначности,
устаревшей оценке и недопустимом скачке. Эта телеметрия может опережать видео.
При остановке поступления кадров GUI сообщает о застывшем изображении.

Изображения не передаются кусками по управляющему UDP; отдельной команды
localisation.debug нет. RTSP-server не используется.

Проверено 98 целевых тестов runtime, 58 unit-тестов GUI, 25 сценариев Qt click
harness без QML warnings, включая запуск/отображение/остановку нового источника.
На реальном CM4 и Mac проверена вся цепочка до декодированного кадра 800×650.
Это проверка диагностики, не подтверждение точности локализации.

С 2026-09-30 рамки ворот показываются после геометрической проверки основания
по карте и только при matched-позе. Надпись `rejected` — число неподтверждённых
цветных кандидатов, включая кадры с неопределённой позой. См.
[проверки ворот](GOAL_COLOUR_LOCALISATION.md).


## Владение кадрами и время жизни подписок

```
camera worker -> roki/camera/frame/v1 (BGR, без H.264)
                |-> localisation worker + roki/motherboard/imu/v1
                |   -> roki/localisation/frame/v1 -> запрашиваемый RTP :5006
                |-> запрашиваемый основной RTP :5004
```

Оба видеоисточника подписываются FrameReader только при video.start.
video.create создаёт лишь описание. Локализатор подписывается на FRAME_TOPIC при
localisation.start; ему не нужен сетевой стрим и он не декодирует H.264.

Разрешены одновременно один runtime и один localisation pipeline. Назначения
должны иметь разные RTP-порты; два потока одного источника и direct-gst вместе
с другим потоком отклоняются. Ошибка или остановка отдельного pipeline не закрывает
другой. Остановка локализации завершает только её видеоподписку. Остановка самой
камеры явно завершает оба зависимых потока. Потеря сессии удаляет принадлежащие ей
потоки, а захват и локализация управляются своими командами.

Внутренний state stream worker теперь возвращает active_streams: список
{stream_id, backend, state}; video.capabilities.max_active=2. Все потребители
обновлены. GUI использует отдельные Video, Receiver и QImageProvider, поэтому
переключение вкладок не перенаправляет общий приёмник. Повторный camera.start
возвращает состояние уже работающего совместимого захвата без перезапуска.
