# Обработанное видео локализации

Во вкладке «Локализация» запустите камеру с IMU и локализацию, затем нажмите
«Видео с разметкой». Активный обычный видеопоток надо сначала остановить:
используется штатный единственный encoder/stream worker. Видео отображается
в этой же вкладке. Остановка видео не останавливает локализацию или камеру.

Поток данных:
1. Камера публикует исходный BGR 800×650 с Unicam sequence и timestamp.
2. Локализатор сопоставляет его с IMU, находит разметку, считает позу.
3. Найденные отрезки и круг проецируются обратно в исходное изображение через
   ту же калибровку и quaternion. На кадре рисуются кандидаты стоек и оценка.
4. Кадр публикуется в `roki/localisation/frame/v1` в формате FRAME_HEADER + BGR,
   сохраняя sequence/timestamp исходного кадра.
5. Stream worker читает этот источник и кодирует обычный H.264/RTP.
6. Оператор декодирует видео в QImage. OpenCV на операторе для этого не нужен.

В существующем video.create добавлено значение backend="localisation".
Sensor не передаётся, максимальный выход 800×650. video.start требует работающих
runtime-камеры и локализатора. Этот backend также доступен в общей панели видео.
Панель локализации использует H.264, 2 Мбит/с, UDP 5004, nominal caps 30 FPS.
Фактическая частота равна частоте вычислений: каждый завершённый обработанный кадр
публикуется, накопления очереди нет, при перегрузке выбирается последний кадр.
Повторные кадры для искусственного повышения FPS не генерируются.

Обозначения:
- синие/жёлтые рамки: цветные кандидаты стоек, не гарантированно настоящие ворота;
- фиолетовый: найденный круг;
- зелёный отрезок: остаток по выбранной гипотезе меньше 10 см;
- оранжевый: больший остаток; серый: нет гипотезы для сравнения.

Зелёные отрезки сами по себе не подтверждают позу: на симметричном поле возможно
несколько решений. Номер кадра, fit_state, число линий/пар ворот и reason нанесены
на сам кадр до кодирования. Русские пояснения текущей телеметрии под видео
сообщают о слабой геометрии, отсутствующем круге/паре стоек, неоднозначности,
устаревшей оценке и недопустимом скачке. Эта телеметрия может опережать видео.
При остановке поступления кадров GUI сообщает о застывшем изображении.

Изображения не передаются кусками по управляющему UDP; отдельной команды
localisation.debug нет. RTSP-server не используется.

Проверено 98 целевых тестов runtime, 58 unit-тестов GUI, 25 сценариев Qt click
harness без QML warnings, включая запуск/отображение/остановку нового источника.
На реальном CM4 и Mac проверена вся цепочка до декодированного кадра 800×650.
Это проверка диагностики, не подтверждение точности локализации.

С 2026-09-30 рамки ворот показываются после геометрической проверки основания
по карте и только при matched-позе. Надпись `rejected` — число неподтверждённых
цветных кандидатов, включая кадры с неопределённой позой. См.
[проверки ворот](GOAL_COLOUR_LOCALISATION.md).
