# Управление камерой из калибровок оператора

Дата: 27.09.2026. **Предложение для согласования с Алексеем Ягубовым.**
Это не описание реализованного API. Рабочий протокол не изменён.

## Согласованные требования

- Настройки камеры рядом с будущими LAB-фильтрами и тестами детекции.
- Ручные выдержка, аналоговое усиление, коэффициенты красного/синего WB.
- Независимое включение AE и AWB, показ фактических значений из метаданных.
- Фиксация найденных автоматикой значений с отключением соответствующей автоматики.
- Возможность оставить автоматику включённой для полевых экспериментов.
- Индивидуальные настройки сохраняются на роботе, не в исходниках образа.

Отсутствие ИК-фильтра учитывается при испытаниях. Ночная настройка не объявляется
проверенной для дневного освещения. Одинаковый сенсор позволяет использовать
общий начальный профиль, но измеренные значения относятся к условиям проверки.

## Выбранный подход

Рекомендуется управление существующим runtime camera-worker и preview через
существующий runtime video backend. Так оператор видит тот же захват, который
получает детектор. Direct-gst остаётся отдельным взаимоисключающим режимом;
его изображение не служит подтверждением применения настроек runtime.

Альтернатива — настройки только при camera.start — проще, но требует перезапуска
захвата и привязки IMU при каждой коррекции. Отдельное управление libcamerasrc
создало бы второй путь настроек и не проверяло бы изображение детектора.

## Предлагаемое расширение протокола

Четыре операции в существующем MessagePack control socket. Доступность определяется
через system.operations. Форматы пикселей, Frame/IMU headers и RTP не меняются.
Примеры ниже — содержимое args внутри существующего request envelope.

### camera.controls.get {}

Доступно наблюдателю. Возвращает requested, measured, revision, saved_revision,
running. Requested содержит ae_enabled, awb_enabled, exposure_us, gain,
red_gain, blue_gain. Measured — null до первого валидного кадра либо объект:
sequence, sensor_timestamp_ns, age_ms, exposure_us, gain, red_gain, blue_gain.
Отсутствующие метаданные имеют значение null, а не requested/defaults.
Остановка камеры очищает measured. Revision — непрозрачная строка, меняющаяся
при изменении настроек и перезапуске сервиса; saved_revision — строка либо null.
GUI запрашивает состояние только при открытой панели, максимум 5 раз/с.

### camera.controls.set

Пример: {"lease_epoch":1,"expected_revision":"r1","values":
{"ae_enabled":false,"awb_enabled":false,"exposure_us":8000,"gain":1.0,
"red_gain":1.19,"blue_gain":2.61}}.

Частичное обновление атомарно проверяется целиком. Ручные exposure_us/gain
допустимы только при итоговом ae_enabled=false; red_gain/blue_gain — только при
итоговом awb_enabled=false. Выдержка не превышает период кадра. Проверяются
конечность чисел, типы и поддерживаемые камерой диапазоны; молчаливого clamp нет.
Для первой версии set требует подготовленный работающий runtime-захват.
Ошибка проверки оставляет настройки неизменными. Direct-gst даёт busy.
Ответ содержит новую revision и requested; принятие команды не означает, что
новые значения уже появились в метаданных. Очередь request не перезапускается.

### camera.controls.freeze

Пример: {"lease_epoch":1,"expected_revision":"r2","groups":["ae","awb"]}.

Робот берёт последний полностью полученный кадр: для ae копирует фактические
выдержку и усиление, для awb — оба коэффициента WB, затем выключает выбранные
автоалгоритмы в одном обновлении. Нельзя смешивать значения из разных кадров.
Не требуется передавать округлённые поля из GUI обратно роботу.
Нет полного набора метаданных, возраст больше 500 мс или камера остановлена —
ошибка без изменения настроек. Возвращает revision, requested и source_sequence.
Freeze не сохраняет файл автоматически и не обещает полного копирования всех
внутренних состояний ISP (например, тональной коррекции).

### camera.controls.save

Пример: {"lease_epoch":1,"expected_revision":"r3"}.

Сохраняет текущие requested и режимы AE/AWB атомарно в каталог состояния робота.
Не снимает значения с продолжающей работать автоматики: для этого сначала freeze.
Можно сохранить авто как выбранный режим эксперимента. Ошибка записи оставляет
старый файл, applied/requested и saved_revision показываются раздельно.
Все изменяющие операции требуют lease; несовпадение expected_revision отклоняется.
Повторы используют существующую дедупликацию request id.

При следующем camera.start сохранённый профиль загружается, явно переданные
старые exposure_us/gain имеют приоритет и задают ручной AE для этого запуска.
Без сохранённого профиля сохраняется существующее поведение старого клиента.
Измеренные коэффициенты 1.19/2.61 выше — пример, не универсальные defaults.

## Интерфейс и проверка

Два переключателя авто, четыре ручных поля, фактические значения отдельно от
запрошенных, возраст измерения, кнопки фиксации AE/WB/обоих и сохранения профиля.
Нет метаданных — «нет измерения». Авто не включается от открытия панели.
Несохранённые изменения явно видны; LAB проверяется на текущем runtime preview.
Старый робот без операций показывает недоступность функции без отправки команд.

До поставки нужны тесты проверки диапазонов/NaN, отсутствующих и устаревших
метаданных, смены revision, потери lease, повторов UDP, сохранения/ошибки записи,
совместимости старого camera.start и максимального ответа до 1200 байт.
На голове: авто → freeze → сравнение метаданных нескольких следующих кадров,
проверка сохранения после restart и непрерывности camera/IMU synchronization.
Проверку движений и пригодности авто для матча этот этап не заменяет.
