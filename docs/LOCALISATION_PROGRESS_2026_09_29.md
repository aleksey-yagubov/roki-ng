# Локализация и оператор: 29 сентября 2026

Статус: диагностическая интеграция. Допуск к игровой локализации не получен.

## Изменения

В рабочую ветку включён origin/main d52e0f5 с двумя изменениями походки.
Настройки и defaults походки не изменялись этой доработкой.

- Адаптивная цветовая модель обучается на уменьшенном изображении, но маска
  вычисляется по исходным пикселям 800×650. Устранена дополнительная ступенчатость
  от увеличения бинарной маски, особенно заметная после проекции на землю.
- Окружность уточняется около предложения Hough по исходной маске; заполненные
  белые пятна отбрасываются по заполнению внутренней области.
- Ассоциация средней линии с центральным кругом работает и с конфигурируемой
  картой; размеры средней линии берутся из карты, без фиксированной ширины.
- Фильтр различает слабое, согласованное и неоднозначное геометрическое совпадение.
  Параллельные отрезки не считаются полным ограничением позиции.
- Worker публикует идентификатор метрической конфигурации и геометрию запуска.
  При исключении старый результат очищается; контроль возраста сохраняется.
- В существующий GUI добавлена вкладка «Локализация»: проверка capabilities,
  камера с IMU, явная начальная поза, старт/стоп, обновление 2 Гц, карта и качество.
  Позиция отображается как диагностический кандидат и исчезает при устаревании.
- Исправлена доступность кнопки детектора и отображение локального отказа команды.

## Проверки и воспроизводимость

85 целевых тестов runtime прошли на Mac, включая локализацию, геометрию,
параметры и совместимость с новыми изменениями походки. На GUI прошли 44 теста.
Модель GUI параметров проверена через настоящий dispatcher и MessagePack:
118 запросов, максимальный пакет 587/1200 байт (аппаратура замокана).
Добавлен отдельный тест максимального сообщения локализации с четырьмя стойками.

На CM4 запущен отдельный simulate supervisor, порт 18093: все пять worker ready,
localisation.status отвечает. Это не проверка физической камеры/движения.
На образе нет pytest; полный Linux suite не запускался.

Для replay:

```sh
python -m tools.check_localisation_replay CAPTURE_DIR CALIBRATION_DIR \
  --prior -1.675 -1.175 .6117 --output /tmp/localisation-replay.json
```

CAPTURE_DIR содержит frame.png и capture.json с quaternion_xyzw и frame_sequence.
CALIBRATION_DIR содержит три legacy npy. Replay обрабатывает одно измерение один
раз, не имитирует новые кадры многократным усилением одного наблюдения.

На сохранённом кадре 912 центральный круг после исправлений снова определяется
на Mac и CM4. На CM4 один замер занял около 1.42 с, 13 отрезков, 23% совпавших,
медианный остаток около 0.31 м. Это всё ещё слабая геометрия. Не считать эти
цифры физической погрешностью позиции; контрольной наземной координаты нет.

## Что остаётся

Нужны свежие кадры с известными положением и позой тела, проверка высоты и
camera/head/body extrinsics, отсев внешней кромки покрытия, устойчивые наблюдения
стоек с подтверждённым основанием, подключение ворот к весам, модель движения,
контроль потери/восстановления и длительные испытания. Нет оснований выставлять
valid=true или использовать кандидат для автономного движения.

GUI показывает прямоугольник и круг из геометрии запуска; цветные стойки остаются
диагностикой, редактор дополнительных меток — в прежней панели «Поле и ворота».
Мастер калибровки объектива и точная синхронизация видеокадра с OSD не реализованы.

## Проверка реального QML через Qt Test

Штатный scripts/test_operator_gui.py расширен: QTest.mouseClick нажимает
кнопки настоящего окна, сообщения идут по UDP к loopback FakeRobot. Пройдены
21 проверка, в том числе capability, старт/стоп локализации, начальный yaw
в радианах и скрытие устаревшей оценки. QML warnings: 0. Qt-артефакты находятся
в GUI artifacts/operator-gui; не включены в Git. Ручная экранная автоматизация
для регрессионной проверки не нужна.

Минимальный размер главного окна теперь 1200×800: нынешние совместные
ограничения KDDockWidgets/панелей не помещаются в прежние 800×700. Панель
локализации прокручивается по вертикали. Компактная компоновка для маленького
экрана остаётся отдельной задачей; уменьшение окна до клиппинга не допускается.

Рабочий сервис /opt/roki-ng в этой итерации не заменён. Проверки CM4 выполнены
из /tmp/roki-localisation-20260929. Профиль оптики находится в прежнем временном
каталоге. Перед проверкой физической точности нужны актуальные положение робота
на поле и поза тела, запрошенные у оператора.
