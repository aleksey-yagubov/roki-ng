# Проверки и их ограничения

## Запуск

```sh
python -m pytest -q -rs
```

Нативная starkit нужна для расчёта настоящих траекторий. Если она собрана
в соседнем checkout, но не установлена:

```sh
PYTHONPATH=../starkit:. python -m pytest -q -rs
```

Часть тестов требует NumPy/OpenCV. Проверки офлайн-прототипов из tools требуют
SciPy, реального IPC - iceoryx2, loopback H.264 - GI/GStreamer с x264enc и декодером.
Отсутствующие необязательные зависимости отмечаются skip; это не успешная
проверка соответствующего компонента. Ручные --ignore для SciPy больше не нужны.
На реального робота этот набор не подключается и движения не отправляет.

При повторном проходе удалены тест передачи topic в mock-конструктор и
проверка повторного subscribe через неизменность размера каталога.
Жизненный цикл походки теперь выполняется через Body.tick(), без принудительного

Тест логов принимает реальные UDP-пакеты от штатного цикла supervisor и проверяет
текст, порядок записей и лимит 1400 байт.

Проверка чувствительности этих тестов: временные подмены в памяти процесса
(пустой прыжок, противоположное направление, пустой цикл ходьбы и неработающий
Body._finish) приводят к провалу соответствующих проверок. Подмены не сохранены
в runtime и не добавлены отдельными тестами. Итог: 498 passed, 5 skipped;
пропущены два SciPy-прототипа, два GStreamer-теста без x264enc и один без iceoryx2.

Весь набор просмотрен по составу; детально переработаны перечисленные группы.
Это не доказательство полезности каждого оставшегося assert. В частности,
часть тестов движения и локализации ещё использует внутренние объекты и mocks.
Не следует переписывать их массово без понимания защищаемого поведения.

## Когда тест нужен

- Он воспроизводит конкретный баг или проверяет наблюдаемый контракт.
- Ожидаемый результат имеет независимое основание: геометрия сцены, формат
  оборудования, правило безопасности, заданные входные данные.
- Mock заменяет границу оборудования/времени, а не вычисление, которое проверяется.
- Тест допускает рефакторинг, сохраняющий поведение. Точный порядок проверяется
  только если он необходим, например IMU до старта камеры или очистка при отмене.
- Для нового случая должно быть понятно, какой ошибочный вариант он обнаружит,
  который не обнаруживают существующие проверки. Число тестов не показатель качества.

## Чего эти проверки не доказывают

Расчёт допустимых углов не доказывает устойчивость на поле и не проверяет нули,
люфты, перегрев, столкновения или правильность геометрии конкретного тела.
Loopback с x264enc не проверяет аппаратный v4l2h264enc CM4.
Синтетические изображения не доказывают точность локализации на реальном поле.
Нужны отдельные стендовые проверки, записи реальных входов и испытания на роботе.
