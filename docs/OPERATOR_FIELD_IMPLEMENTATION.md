# Настраиваемая карта и камера: первый этап реализации

28.09.2026. Изменения локально в roki-ng и roki-ng-operator-gui, не установлены
в рабочий сервис робота. Полная исходная задача ещё не закрыта.

## Что работает в исходниках

- Расширена существующая Parameters, без второго config store. Новый тип object
  описывается `fields` в params.describe. 19 составных field-параметров и
  match.own_goal, атомарное сохранение каждого объекта, optional expected_value.
- Геометрия игрового прямоугольника, покрытия, центрального круга; две записи
  ворот с цветами/размерами; 16 отключаемых крестов/колец/дисков/отрезков.
- Qt-панель карты, численный редактор, перемещение выбранного объекта мышью,
  добавление/выключение меток, defaults, сохранение/отмена черновика, свои ворота.
- Локализация получает снимок Parameters на старте: размеры больше не зашиты
  в модели. Кресты/отрезки входят как линии, кольца — альтернативные ассоциации;
  при дополнительном кольце центральная линия не привязывается по одному лишь
  факту пересечения любого найденного круга. Радиус используется только когда
  он указан как измеренный для центрального круга.
- Пороги ворот берутся из общей LAB-схемы. Разметка: адаптивный режим либо
  сохранённые LAB-диапазоны. Изменение vision.* доставляется обоим worker-ам;
  старая ревизия результата не публикуется после изменения.
- Выдержка/gain/AE/AWB и ручной WB доступны в существующем редакторе params;
  camera-worker передаёт изменения следующему Request без stop/configure.
  Высота камеры также параметр, применяется на следующем старте локализации.

Полный контракт: [OPERATOR_PROTOCOL.md](OPERATOR_PROTOCOL.md).
Инструкция GUI: `roki-ng-operator-gui/docs/FIELD_EDITOR.md`.

## Defaults и перенос

Поле 3.35×2.35 м, покрытие 4×3 м. Круг 0.5 м, ворота 1.0×0.6 м — только
шаблонные размеры (measured=false), а не новые измерения этого поля. Перед
метрическим использованием задайте реальные значения. Дополнительные метки
изначально выключены. Верхние/нижние цвета по умолчанию синий/жёлтый, свои — 0;
назначение нужно сверить с полем и стартовой позой.

При переносе старого локального profile.json перенесите его camera_height_m
в новый параметр localisation.camera_height_m, если он отличается от 0.4068.
Выбор legacy npy и режим 800×650 пока остаются прежними. Сам measured-флаг
не является подтверждением точности; оператор ставит его после измерения.

## Проверки

На Mac: целевые тесты runtime/локализации/камеры — 54 passed на момент добавления
controls и карты; полный runtime — 166 passed, 2 skipped, 6 failed. Шесть
процессных тестов блокируются отсутствием нужного Unix seqpacket IPC на macOS.
GUI-модель поля — 5 passed. Старые сетевые GUI-тесты: 1 passed, 11 failed,
поскольку транспорт явно не поддерживает macOS. Отдельный Qt Quick render
FieldPanel выполнен, изображение проверено. Новые camera-controls проверены
mock Request, а не на настоящем сенсоре.

## Оставшаяся работа

Следующим этапом добавлена встроенная панель цветов/камеры в существующий
Operator.qml: пипетка, LAB-ползунки/preview, роботный detection.status, runtime
video backend, атомарный params.set и camera.controls.freeze. Проверены
62 целевых runtime-теста и 13 GUI-тестов, реальный Qt-клик по пипетке и вкладка
камеры. Контракт моделей GUI и dispatcher проверен через MessagePack: 166
запросов, наибольший пакет 587/1200 байт, hardware mocked. Инструкция —
`roki-ng-operator-gui/docs/VISION_TUNING.md`.

Полный runtime после этого этапа: 174 passed, 2 skipped, 6 failed; остаются те
же шесть платформенных процессных ошибок на macOS. Полный набор не зелёный.

Нет полной панели калибровки объектива и атомарного применения многокомпонентного
профиля поля. Нет отдельных надёжных
детекторов дисков/коротких крестов и метрического включения ворот. Редактор
сохраняет эти объекты, но не заявляет, что все они распознаются. Нет hardware
подтверждения новых controls и сквозной проверки Linux Qt → robot → кадр.
После этих этапов остаются метрические испытания и условия допуска valid=true,
описанные в LOCALISATION_RUNTIME_STATUS.md.
