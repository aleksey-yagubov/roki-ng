# Продолжительная работа камеры и локализации

IMU STM выдаёт uint16 sequence. Ранее ImuPublisher останавливал захват при
переходе через 65535, примерно через 18 минут при 60 кадрах/с. Supervisor после
этого корректно останавливал зависимые камеру, локализацию и стрим, однако GUI
оставлял последнюю картинку и занятый идентификатор потока.

Теперь счётчик расширяется до uint32 внутри текущего захвата перед публикацией
в существующий IMU_RECORD (<IQffffI). Размер записи и названия каналов не меняются.
SequenceJoiner сравнивает расширенные номера, без операции modulo при соединении:
IMU 3 и кадр 65539 не являются парой. Допускаются запоздалые записи предыдущего
оборота в пределах 256 номеров; явный сброс счётчика назад требует перезапуска
захвата. Начало нового захвата создаёт новый ImuPublisher и выравнивание.

Тесты покрывают оба порядка прихода кадра/IMU, дубликаты, запоздалую запись около
переполнения, сброс, два полных оборота счётчика (131200 измерений) и ограничение
памяти. Аппаратное прохождение полного оборота после исправления ещё нужно
проверить длительным запуском; программный тест не заменяет эту проверку.

GUI при video.status=stopped показывает сообщение об остановке на роботе,
останавливает приёмник и уничтожает оставшийся объект потока. После этого
доступен новый запуск. Автоматически запускать камеру или движение он не начинает.
