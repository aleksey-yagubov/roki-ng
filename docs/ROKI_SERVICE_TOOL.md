# Roki Service Tool: отложенный проект

Требования владельца, 2026-09-25. Реализацию пока не начинать.

Отдельная простая сервисная программа для компьютера. Не зависит от головы
робота, supervisor, motherboard-worker или запущенного roki-ng.

## Два способа подключения

1. Через контроллер Зубр по USB CDC ACM. Пользователь выбирает системный
   порт (обычно /dev/ttyACM*). Программа использует протокол контроллера,
   получает доступ к сервам на его каналах. Адрес сервы: канал и deviceId.
2. Напрямую через USB-RS485 адаптер. Пользователь выбирает /dev/ttyUSB*
   или /dev/ttyACM*, в зависимости от адаптера. На одной шине могут быть
   одна или несколько серв. Программа использует протокол серв без контроллера
   Зубр и без motherboard. Адрес сервы: deviceId в пределах выбранной шины.

Предусмотреть общий интерфейс сервисных операций с двумя транспортными
реализациями. Нельзя отправлять протокол контроллера напрямую сервам.
Скорость, формат UART и управление направлением RS485 должны соответствовать
оборудованию; возможность автоматического переключения направления адаптером
нужно проверить. Не открывать один порт несколькими программами одновременно.

## Функции

- Быстрый поиск серв: сигнатура, версия, ID, канал при работе через контроллер.
- Чтение и редактирование всех поддерживаемых параметров, с учётом модели,
  версии, доступа R/RW и проверкой результата записи.
- Обновление прошивок серв строго последовательно, по одной серве,
  с проверкой ответов и состояния между этапами.
- Установка фабричных лимитов: уточнить точную семантику команды сервы,
  не путать с записью лимитов конкретного робота из .robot.
- Повторение функции IronArt «Обнулить позиции сервомоторов»: назначение
  текущего физического положения нулём, а не движение в нулевую позу.
- Напрячь, расслабить, задать положение выбранной серве; ручное безопасное
  перемещение для проверки работы.

Подробный рабочий каталог параметров хранится локально и не публикуется.
Настройки робота и будущий mailbox: [SERVO_MANAGEMENT.md](SERVO_MANAGEMENT.md).
В этой программе mailbox не является обязательным: используются прямые
сервисные протоколы соответствующего подключения.

## Скорость поиска

Не повторять долгий фиксированный перебор IronArt с многочисленными ожиданиями
на каждом отсутствующем ID. Дать выбор канала, диапазона ID и известного профиля;
для одной подключённой сервы позволить сразу указать ID. Использовать
ограниченные таймауты и повторные попытки, немедленно переходить дальше после
валидного ответа. Не допускать коллизий ответов нескольких серв на одной шине.
Кэш результатов не заменяет проверку идентичности перед записью или прошивкой.
Точные таймауты определить измерениями, а не произвольным сокращением.

## Обновление прошивок

Владелец наблюдал неработоспособные сервы после выбора нескольких устройств
в IronArt; отдельная прошивка одной сервы работала. Причина не установлена.
В просмотренном IronArt выбор нескольких уже обрабатывается последовательно,
поэтому одного цикла «для каждой сервы» недостаточно для устранения проблемы.

- Проверять HEX, контрольные суммы, диапазоны адресов и совместимость модели
  до стирания. Не определять совместимость только по имени файла, как IronArt.
- Прошивать только одну серву в каждый момент, исключить обычное управление
  и конкурирующие сервисные запросы во время операции.
- Проверять переход в загрузчик, завершение стирания и ответы на запись.
- Привязывать ответы к ожидаемому этапу и устройству; запоздалый статус
  предыдущей операции не должен завершать следующую.
- Если загрузчик поддерживает чтение/CRC, проверять записанный образ.
  Не выдавать подтверждение записи слова за проверку всего образа.
- После запуска приложения заново проверить связь, сигнатуру и версию;
  только затем переходить к следующей выбранной серве.
- При ошибке остановить пакетное обновление, сохранить журнал и показать
  состояние текущей сервы и возможность восстановления. Не стирать следующую.
- Отмена должна учитывать текущий этап: прерывание после стирания может
  оставить серву только с загрузчиком. Явно предупреждать об этом.

## Безопасность и неизвестные детали

Обнуление и запись лимитов выполнять только после явного подтверждения,
в правильной физической позе и без нагрузки, способной уронить робота.
Не поднимать тепловые пороги автоматически в универсальной сервисной программе.
Фабричный сброс не должен случайно менять ID, скорость или другие настройки.

До реализации проверить протокол и загрузчик каждой поддерживаемой версии,
сохранение параметров во flash, назначение специальных команд и поведение
адаптеров RS485. Поддержка операций одним транспортом не доказывает автоматически
их поддержку другим. Исходники IronArt и Зубра использовать как справочник,
а не переносить их проверки ошибок без анализа.
