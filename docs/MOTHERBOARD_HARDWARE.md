# Периферия motherboard STM32

Данные пользователя по блок-схеме, 2026-09-25. MCU: STM32H743VIT.
Это описание соединений, а не подтверждение соответствия установленного бинарника.

| Периферия | Выводы STM | Соединение и назначение |
|---|---|---|
| UART7 | PE7 RX, PE8 TX | Внешний разъём, не используется |
| USART3 | PD8 TX, PD9 RX | UART5 Raspberry Pi; сейчас runtime и загрузчик, после перехода на ACM только загрузчик |
| UART4 | PC10 TX, PC11 RX | UART2 Raspberry Pi; план отдельного IMU-канала отменён |
| UART8 | PE0 RX, PE1 TX | Основной канал тела, 1250000 бод |
| I2C1 | PB6 SCL, PB7 SDA | Внешний разъём, не используется |
| CAM_SYNC | PC0 | Не используется; оставить Hi-Z без подтяжек |
| STROBE | PE9 | Строб камеры 1,8 В, требуется для синхронизации IMU |
| SPI1 | PA5 CLK, PA6 MISO, PA7 MOSI | IMU головы |
| IMU interrupt | PA9 | Вход прерывания IMU |
| IMU reset | PA10 | Сброс IMU |
| IMU CS | PE15 | Выбор IMU на SPI |
| USB | PA11 DM, PA12 DP | Подтверждён через внутренний хаб; CDC ACM, product Roki motherboard, Full Speed |

## Расхождения с просмотренными исходниками

Ниже историческая проверка оригинала. Для следующей версии выбран полный
runtime через ACM: [MOTHERBOARD_PROTOCOL_V2.md](MOTHERBOARD_PROTOCOL_V2.md).
Совместимость старого application UART RPC больше не требуется; загрузчик
сохраняется. Ограничения первоначального аудита ниже не отменяют это решение.

Сверено с tndrd/roki-mb-firmware, commit
`4f90df4a5622404dc2a26c02146f235259e44d4f`.

- UART4 настроен на PA0/PA1, а не PC10/PC11. Для будущего IMU-канала
  нельзя просто использовать существующую инициализацию без исправления pinmux.
- Инициализируется I2C2 на PB10/PB11, а не указанный на схеме I2C1.
- Дополнительно инициализируется USART2 на PA2/PA3; назначения в предоставленной
  блок-схеме нет. Кандидат на удаление после проверки использования.
- PE9 используется как аналоговый вход COMP2, с прерываниями по обоим фронтам.
  Порог COMP2 берётся от DAC1 CH1. Поэтому COMP2 и DAC1 являются частью
  приёма строба, их нельзя удалять как неиспользуемые. Пользователь подтвердил
  питание сенсора 1,8 В; сохраняем эту схему согласования уровней.
- CAM_SYNC PC0 настроен как push-pull выход с начальным низким уровнем.
  В новой прошивке не управлять этой линией, оставить Hi-Z без подтяжек.
  Пользователь проверял работу камеры с физически неподключёнными линиями sync.
  При переходе из кастомного загрузчика проверить унаследованное состояние PC0:
  если загрузчик включил выход, явно перевести только этот пин в Hi-Z.
- USB CDC инициализируется, но обработчик приёма не передаёт данные в RPC.
  Основной RPC работает через USART3. Наличие ttyACM не означает готовность
  протокола motherboard через USB; принадлежность устройства и путь через хаб
  нужно проверить аппаратно.

## Ограничения при доработке

- Сначала сохранить загрузчик и основной UART-протокол; не прошивать автоматически.
- Для camera strobe оставить сохранение IMU головы без блокирующего опроса тела.
- Второй UART и USB рассматривать как отдельные последующие изменения.
- Не запускать неиспользуемую периферию. UART7 и I2C1 не нужны; имеющиеся
  инициализации I2C2 и USART2 проверить и удалить, если нет потребителей.
  UART4 запускать только при реализации отдельного IMU-канала.
- Удалять неиспользуемые инициализации вместе с их DMA/IRQ только после проверки
  зависимостей. Тактирование GPIO-банка не означает использование всех его пинов.
- ST-Link и DAPLink доступны у пользователя для отладки/восстановления.
