# Настройка thresholds и проверка зрения без игры

Для первых проверок достаточно зелёной ткани и мяча. Команды диагностики
не двигают тело или голову и не включают игру. Камеру запускает оператор.
Проверка дальности требует известной высоты камеры; для расслабленного робота
на стойке сначала проверяйте маски, а не точность метров.

## 1. Подготовить камеру

Взять управление, выбрать MANUAL. В «Камере» запустить runtime-захват с IMU,
дождаться synced. Direct-gst даёт видео, но не снабжает детекторы кадрами.
В «Стримах» смотреть camera. Проверить освещение, экспозицию и баланс белого;
при использовании автоматов дать им установиться, затем зафиксировать и
сохранить controls. Изменение ISP после настройки меняет цвета и требует
повторной проверки thresholds. Жёлтое изображение не следует исправлять
расширением оранжевого фильтра.

## 2. Настроить цвета

В «Зрении» загрузить настройки. Выбрать исходный приёмник camera и профиль.
Порядок для мяча: green_field, white_marking, orange_ball. Белый профиль тоже
участвует в проверке окружения мяча; неверный белый фильтр может принимать фон.

- Зафиксировать кадр или включить Live; щелчок по образцу создаёт черновик
  порогов по области 7×7. Локальная маска приблизительная: видео уже сжато.
- L: 0…100; a и b: −128…127. Границы включительные, минимум ≤ максимума.
- pixels_min: число пикселей связной цветной области, пиксели.
  box_area_min: ширина × высота её рамки, пиксели². Эти значения независимы.
- «Сохранить фильтр» записывает `vision.<профиль>.*` обычным params.set.
  Робот применяет целый набор к следующему кадру, без перезапуска камеры.
  Несохранённые ползунки не изменяют роботный детектор.

Выбрать «LAB: выбранный цвет» → «Запустить проверку». В «Стримах» обновить
список, выбрать detection → «Смотреть». Изображение появится и в «Зрении»:
слева исходник с рамками прошедших фильтры областей, справа роботная маска.
area_rejected показывает число отброшенных по площади компонентов; отсутствие
рамки при наличии белого пятна в маске может быть следствием именно этого.
Для смены проверяемого профиля остановить и снова запустить проверку.
Проверить не только образец цвета, но и фон: руки, стены, стойку, блики.

## 3. Проверить настоящий детектор мяча

Остановить LAB-проверку. Выбрать «Мяч: игровой алгоритм + IMU», запустить.
Нужны профиль оптики в state-dir/localisation и синхронные кадры/IMU.
При ошибке профиля исправить её, а не менять thresholds. Игра должна быть
остановлена; запуск диагностики не изменяет позу робота.

Снова смотреть detection. Четыре панели: исходник с решениями, оранжевая
маска, зелёная и белая маски окружения. Номер кадра, ревизия и время обработки
напечатываются на самом видео. Данные статуса приходят независимо: сверять
по frame_sequence, не считать последнюю строку статуса подписью к старому видео.

| Решение | Что проверить |
| --- | --- |
| selected | Геометрический кандидат выбран; результат пригоден только при valid=true и свежем кадре |
| area_rejected | Слишком мала цветная область или её рамка; проверить маску и минимальные площади |
| no_field | Нет связного зелёного/белого участка от 7 пикселей справа, слева или снизу от мяча |
| projection | Луч выше/слишком близко к горизонту либо вне калиброванной области; проверить наклон и профиль |
| range | Проекция позади камеры, некорректна или дальше game.ball_max_distance_m |
| no_sync | Пока нет пары кадр–IMU |
| stale | Измерение старше 0,5 с; не использовать как текущую позицию мяча |

Проверяются максимум десять нижних по центроиду подходящих оранжевых областей,
до первого принятого кандидата. Остальные не объявляются отклонёнными.
Это тот же отбор, что у игры, не отдельная имитация.

X — вперёд, Y — влево относительно направления головы; единицы — метры.
Для проверки дальности установить робота в известную позу, измерить высоту
камеры до ткани и проверить `game.camera_height_m`, диаметр —
`game.ball_diameter_m`. Диагностика сама не подтверждает опорную позу и не
компенсирует произвольное провисание расслабленного тела. Поставить мяч в
несколько измеренных точек вперёд/влево/вправо, сравнить координаты. Затем
убрать мяч: детектор должен перестать выдавать valid=true; добавить оранжевый
предмет без зелёного/белого окружения — проверить no_field.

## 4. Линии, круг, ворота

Их существующая диагностика — панель «Локализация» и источник localisation.
Проверить режим сегментации: фиксированные LAB-пороги и адаптивная сегментация
не тождественны. На маленькой ткани можно оценить маски и отдельные наблюдения,
но нельзя подтвердить точность позиции на поле, круг и геометрию ворот.

При отдельном запуске локализации камера должна быть в известной неподвижной
позе; prior задаёт направление головы. Для сравнения с координатами тела
держать pan=0 и измерить `localisation.camera_height_m`. Однозначная пара стоек
может определить позицию без линий; симметричная белая разметка сама по себе
не определяет сторону. valid=true означает пригодное свежее сопоставление,
не измеренную точность. Параллельные линии, слабые и неоднозначные наблюдения
не должны выдавать пригодную позицию.

Во время игры локализатор запускается стратегией, берёт высоту из
`game.camera_height_m` и получает привязанный к полю курс IMU. Только три
согласованных кадра в стойке дают поправку; последнюю видно в панели игры.
На движении измерения не применяются. Просмотр localisation доступен, ручные
start/stop во время игры запрещены. Нет ориентиров — сохраняется одометрия.

Видео диагностики создаётся только при подписке, не чаще 5 Гц. Ошибка его
передачи не выключает детектор. Остановка проверки выключает только её и её
видеопоток; камера остаётся включённой. Не оставляйте старую картинку без новых
кадров основанием для оценки — проверяйте возраст/status. Эти проверки не
заменяют безопасные испытания движений и игры на настоящем поле.
