# Правила разработки

- Проект находится в активной переработке. Не добавлять совместимость со старыми
  ключами параметров, API и протоколами без прямого запроса пользователя:
  никаких алиасов, миграций или временных заглушек старых интерфейсов.
- GUI и роботный runtime обновляются синхронно. Не вводить версии/согласование
  версий операторского протокола, capabilities и внутренних IPC-каналов.
  Это не относится к протоколам оборудования и форматам сохраняемых файлов.
- Тест проверяет наблюдаемое поведение, инвариант безопасности или конкретную
  регрессию, а не копирует реализацию. Не закреплять удалённые API, тексты
  описаний и произвольный порядок независимых операций. Вместо декартовых
  переборов использовать обоснованные сценарии и границы; число тестов не цель.
- При изменении интерфейса обновлять потребителей, тесты и документацию.
  Отсутствующие параметры получают текущие значения по умолчанию.
- Действующие дефолты согласованы пользователем как базовая рабочая конфигурация,
  которая не роняет робота. Сохранять их при рефакторинге; изменение дефолтов
  требует отдельного обоснования. Это не гарантия для неисправного/иначе собранного
  тела или произвольных сочетаний изменённых параметров.
- Оптимизации ручных движений не переносить автоматически в автономную игру.
